Formularios y validación

Los formularios son el canal principal entre el usuario y el servidor. JavaScript permite interceptar el envío, validar los datos antes de que salgan del navegador y dar feedback inmediato sin recargar la página.

El evento submit

Cuando un usuario envía un formulario se dispara el evento submit en el elemento <form>. Para evitar que la página se recargue (el comportamiento por defecto), llamas a e.preventDefault().

evento-submit.js 
const form = document.querySelector('#registro');

form.addEventListener('submit', e => {
  e.preventDefault(); // evita recargar la página

  const data = new FormData(form);
  console.log(Object.fromEntries(data)); // { nombre: "...", email: "..." }
});

FormData

FormData es una API que captura todos los campos del formulario automáticamente. Puedes leer los valores con get o convertirlo a un objeto plano con Object.fromEntries.

formdata.js 
form.addEventListener('submit', e => {
  e.preventDefault();

  const fd = new FormData(form);

  console.log(fd.get('nombre'));       // valor del input name="nombre"
  console.log(fd.has('email'));        // true si el campo existe
  console.log([...fd.entries()]);      // pares [nombre, valor]
});

Validación HTML5 nativa

HTML5 ofrece atributos de validación sin escribir JavaScript: required, minlength, maxlength, min, max, pattern y type. El navegador muestra mensajes por defecto y bloquea el envío si algo falla.

validacion-html5.html 
<form>
  <input type="email" name="email" required>
  <input type="text" name="usuario" minlength="3" maxlength="20" required>
  <input type="number" name="edad" min="18" max="120">
  <input type="text" name="codigo" pattern="[A-Z]{3}[0-9]{3}">
  <button type="submit">Enviar</button>
</form>

Constraint Validation API

Para personalizar los mensajes de error o validar desde JavaScript usa la Constraint Validation API. Cada campo tiene propiedades como validity, validationMessage y el método setCustomValidity.

constraint-validation.js 
const email = form.querySelector('#email');

email.addEventListener('blur', () => {
  if (email.validity.valueMissing) {
    email.setCustomValidity('El email es obligatorio');
  } else if (email.validity.typeMismatch) {
    email.setCustomValidity('Formato de email inválido');
  } else {
    email.setCustomValidity(''); // limpia el mensaje
  }

  console.log(email.validationMessage); // mensaje actual
  console.log(email.validity.valid);    // true / false
});

Puedes consultar el objeto validity para detectar problemas específicos: tooShort, patternMismatch, rangeOverflow, etc.

Validación manual

A veces necesitas lógica que la validación HTML5 no cubre (comparar dos contraseñas, comprobar un formato personalizado, etc.). En ese caso recorres los campos y muestras errores manualmente.

validacion-manual.js 
form.addEventListener('submit', e => {
  e.preventDefault();

  const pass = form.querySelector('#password').value;
  const confirm = form.querySelector('#confirmar').value;

  if (pass !== confirm) {
    mostrarError('Las contraseñas no coinciden');
    return;
  }

  enviarDatos(); // todo OK
});

function mostrarError(msg) {
  const div = document.createElement('div');
  div.textContent = msg;
  div.className = 'error-msg';
  form.prepend(div);
}

La validación del frontend es solo para UX. Nunca confíes solo en la validación del navegador. Un atacante puede enviar peticiones directamente a tu servidor sin pasar por el formulario. Siempre debes validar y sanitizar los datos también del lado del servidor.
