Delegación de eventos

Si añades un listener a cada elemento de una lista, el rendimiento se resiente y el código se vuelve difícil de mantener. La delegación usa el burbujeo para escuchar desde un solo padre, incluso para elementos que aún no existen.

El problema

Imagina una lista de 100 elementos y quieres que cada uno responda al click. Si pones un addEventListener por cada <li>, creas 100 funciones en memoria. Si además los elementos se añaden dinámicamente, tienes que acordarte de suscribir cada nuevo nodo.

problema.js 
// ❌ Ineficiente: un listener por cada item
document.querySelectorAll('.item').forEach(item => {
  item.addEventListener('click', () => {
    console.log('click en', item.textContent);
  });
});

// Los nuevos items añadidos después NO tendrán listener

La solución: delegación

Coloca un solo listener en el contenedor padre y usa event.target para saber qué hijo concreto disparó el evento. Como el evento burbujea desde el hijo hasta el padre, el padre lo recibe y puedes filtrar.

delegacion.js 
const lista = document.querySelector('ul');

lista.addEventListener('click', e => {
  const item = e.target.closest('li');
  if (!item) return; // no era un <li>

  console.log('click en', item.textContent);
});

// Ahora funciona también para <li> añadidos después
const nuevo = document.createElement('li');
nuevo.textContent = 'Dinámico';
lista.appendChild(nuevo); // el click se capturará igual

Usa closest para filtrar. e.target puede ser un hijo interno (como un <span> dentro del <li>). closest('li') sube hasta el ancestro que buscas, y si no lo encuentra devuelve null.

event.target vs event.currentTarget

Es importante distinguirlos: e.target es el elemento que originó el evento (donde hiciste click), mientras que e.currentTarget es el elemento donde está atado el listener (el padre). En delegación casi siempre quieres trabajar con e.target.

target-vs-currenttarget.js 
lista.addEventListener('click', e => {
  console.log('target:', e.target);        // el <li> o <span> clickeado
  console.log('currentTarget:', e.currentTarget); // siempre <ul>
});

Delegación en tablas

El patrón es el mismo para estructuras más complejas como tablas. Un solo listener en <table> y filtras por el botón o celda que te interesa.

delegacion-tabla.js 
document.querySelector('table').addEventListener('click', e => {
  const btn = e.target.closest('.btn-eliminar');
  if (!btn) return;

  const fila = btn.closest('tr');
  fila.remove();
});

Ventajas de la delegación

  • Rendimiento: un solo listener en vez de cientos.
  • Elementos dinámicos: funciona con nodos que se añadan después de registrar el listener.
  • Menos código: no necesitas bucles para suscribir ni limpiar listeners al eliminar elementos.
  • Menos memoria: una sola función en memoria en lugar de una por elemento.

La delegación es uno de los patrones más prácticos del DOM moderno. En el próximo tema verás cómo aplicarlo a la validación de formularios.
