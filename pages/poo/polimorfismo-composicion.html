Polimorfismo y composición vs herencia

El polimorfismo permite que objetos distintos respondan al mismo mensaje de formas diferentes. La composición, por su parte, te permite construir objetos combinando piezas pequeñas en lugar de heredar jerarquías rígidas.

Polimorfismo: misma interfaz, distinto comportamiento

En JavaScript el polimorfismo se da de forma natural gracias al duck typing: si un objeto tiene el método que esperas, puedes tratarlo como si fuera de ese tipo, sin importar su clase.

polimorfismo.js 
class Pato {
  hacerSonido() {
    console.log("¡Cuac!");
  }
}

class Gallo {
  hacerSonido() {
    console.log("¡Quiquiriquí!");
  }
}

function ejecutarSonido(animal) {
  animal.hacerSonido();
}

ejecutarSonido(new Pato());  // "¡Cuac!"
ejecutarSonido(new Gallo()); // "¡Quiquiriquí!"

No importa que Pato y Gallo compartan o no una clase padre. Lo único que necesita ejecutarSonido es que el argumento tenga un método hacerSonido.

Duck typing

"Si camina como pato y suena como pato, entonces es un pato". Así funciona el tipado en JavaScript: no te fijas en la herencia, te fijas en las capacidades del objeto.

duck-typing.js 
function volar(cosa) {
  if (typeof cosa.volar === "function") {
    cosa.volar();
  } else {
    console.log("Esto no vuela");
  }
}

const pajaro = { volar: () => console.log("volando alto") };
const avion = { volar: () => console.log("despegando") };
const piedra = {};

volar(pajaro); // "volando alto"
volar(avion);  // "despegando"
volar(piedra); // "Esto no vuela"

Herencia vs composición

La herencia modela relaciones de tipo "es un" (is-a). La composición modela "tiene un" (has-a). En la práctica, la composición suele ser más flexible.

composicion.js 
// Composición: un objeto se forma combinando otros objetos
const puedeVolar = {
  volar() { console.log("volando..."); }
};

const puedeNadar = {
  nadar() { console.log("nadando..."); }
};

function crearPato() {
  return Object.assign({}, puedeVolar, puedeNadar);
}

const pato = crearPato();
pato.volar(); // "volando..."
pato.nadar(); // "nadando..."

Comparación: herencia vs composición

AspectoHerenciaComposición
Relación"es un" (is-a)"tiene un" (has-a)
AcoplamientoAlto (hijos atados al padre)Bajo (piezas intercambiables)
FlexibilidadMenor (jerarquías rígidas)Mayor (combina lo que necesitas)
ReutilizaciónVía herencia verticalVía mixins / objetos pequeños
Problema típicoProblema del diamante, jerarquías profundasMás archivos/objetos que gestionar

Mixins con Object.assign

Los mixins son una forma de componer comportamientos copiando métodos de un objeto a otro. Object.assign es la herramienta perfecta para esto.

mixins.js 
const conRegistro = {
  registrar(accion) {
    if (!this.acciones) this.acciones = [];
    this.acciones.push({ accion, timestamp: Date.now() });
  },
  historial() {
    return this.acciones;
  }
};

class Ventana {
  abrir() { this.registrar("abrir"); }
  cerrar() { this.registrar("cerrar"); }
}

Object.assign(Ventana.prototype, conRegistro);

const v = new Ventana();
v.abrir();
v.cerrar();
console.log(v.historial().length); // 2

Regla práctica: prefiere herencia solo cuando tengas una relación clara de "es un" y la jerarquía sea estable (pocos niveles). Usa composición cuando necesites combinar comportamientos de forma flexible o cuando la jerarquía de herencia se vuelva un árbol de Navidad.
