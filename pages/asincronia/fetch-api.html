fetch API y consumo de APIs REST

fetch es la forma nativa de JavaScript para hacer peticiones HTTP. Reemplaza al viejo XMLHttpRequest y devuelve una promesa, lo que la hace ideal para combinarla con async/await.

GET con fetch

La forma más básica: fetch(url) inicia una petición GET. El método devuelve una promesa que resuelve con un objeto Response. Para leer el cuerpo en JSON usamos .json().

get-fetch.js 
async function obtenerPosts() {
  const respuesta = await fetch("https://jsonplaceholder.typicode.com/posts");
  const posts = await respuesta.json();
  console.log(posts);
}

obtenerPosts();

POST con headers y body

Para enviar datos, pasamos un objeto de opciones con method, headers y body. El cuerpo debe ser un string JSON, no un objeto literal.

post-fetch.js 
async function crearPost() {
  const respuesta = await fetch("https://jsonplaceholder.typicode.com/posts", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      title: "Nuevo post",
      body: "Contenido del post",
      userId: 1
    })
  });
  const post = await respuesta.json();
  console.log(post);
}

Manejo de errores HTTP

fetch solo rechaza la promesa si hay un error de red (como falta de conexión). Un 404 o un 500 son respuestas HTTP válidas, así que fetch no las trata como error. Debes verificar response.ok manualmente.

fetch no rechaza errores HTTP. Si la API devuelve 404 o 500, la promesa se resuelve igual. Siempre revisa response.ok o response.status y lanza un error tú mismo si es necesario.

manejo-errores-fetch.js 
async function obtenerUsuario(id) {
  const respuesta = await fetch(`https://api.example.com/usuarios/${id}`);

  if (!respuesta.ok) {
    throw new Error(`Error HTTP: ${respuesta.status} ${respuesta.statusText}`);
  }

  return await respuesta.json();
}

Abortar una petición con AbortController

Si el usuario navega a otra página o la petición tarda demasiado, puedes cancelarla con AbortController. Conectas la señal del controlador a la petición fetch y llamas a .abort() cuando quieras cancelar.

abort-controller.js 
async function buscarConTimeout(url, timeoutMs = 5000) {
  const controller = new AbortController();
  const timeout = setTimeout(() => controller.abort(), timeoutMs);

  try {
    const respuesta = await fetch(url, { signal: controller.signal });
    return await respuesta.json();
  } catch (error) {
    if (error.name === "AbortError") {
      throw new Error("Petición cancelada por timeout");
    }
    throw error;
  } finally {
    clearTimeout(timeout);
  }
}

Buenas prácticas al usar fetch

  • Siempre verifica response.ok antes de leer el cuerpo.
  • Usa try/catch para capturar tanto errores de red como errores HTTP lanzados manualmente.
  • Agrupa la lógica de fetch en funciones reutilizables con una base URL común.
  • Considera usar AbortController en componentes que se montan/desmontan para evitar fugas de memoria.

Con fetch y async/await ya puedes consumir cualquier API REST moderna. El siguiente paso es manejar los errores que inevitablemente ocurrirán en producción.
