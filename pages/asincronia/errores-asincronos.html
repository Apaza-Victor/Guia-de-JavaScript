Manejo de errores asíncronos

El código asíncrono introduce una dificultad extra: un error puede ocurrir después de que el bloque try/catch original ya terminó. Aprender a capturar errores en promesas, async/await y eventos globales es esencial para aplicaciones robustas.

try/catch con async/await

La forma más directa: la función async envuelve la lógica en un try/catch igual que código síncrono. Si cualquier await dentro del bloque falla, salta al catch.

try-catch-async.js 
async function cargarDatos() {
  try {
    const respuesta = await fetch("/api/datos");
    if (!respuesta.ok) throw new Error(`HTTP ${respuesta.status}`);
    return await respuesta.json();
  } catch (error) {
    console.error("Error al cargar datos:", error.message);
    return { error: true, datos: [] };
  }
}

.catch() en promesas encadenadas

Con promesas, el .catch() al final captura cualquier error que ocurra en cualquier .then() anterior, igual que un try/catch abarcaría todo el bloque.

catch-encadenado.js 
fetch("/api/usuarios")
  .then(respuesta => {
    if (!respuesta.ok) throw new Error("Error HTTP");
    return respuesta.json();
  })
  .then(usuarios => console.log(usuarios))
  .catch(error => console.error("Algo falló:", error.message));

Unhandled Promise Rejection

Cuando una promesa se rechaza y no tiene un .catch() asociado (ni un await dentro de un try/catch), el motor genera un unhandled promise rejection. En el navegador aparece como advertencia en la consola; en Node.js puede terminar el proceso.

Siempre captura tus promesas. Una promesa rechazada sin manejar no solo ensucia la consola: en Node.js desde la versión 15, el proceso termina con código de error. Si trabajas con promesas sueltas, asígnales siempre un .catch().

unhandled-rejection.js 
// Esto genera un unhandled rejection
Promise.reject(new Error("Fallo sin captura"));

// Esto lo captura correctamente
Promise.reject(new Error("Fallo capturado"))
  .catch(error => console.error(error.message));

Capturar errores globalmente

Para evitar que una rejection no capturada se escape, puedes escuchar el evento global unhandledrejection en el navegador, o process.on('unhandledRejection') en Node.js. También existe window.onerror para errores síncronos no capturados.

global-error-handler.js 
// En el navegador
window.addEventListener("unhandledrejection", event => {
  console.error("Promesa no capturada:", event.reason);
  event.preventDefault(); // evita la advertencia en consola
});

// En Node.js
process.on("unhandledRejection", (motivo, promesa) => {
  console.error("Rejection no manejada:", motivo);
});

Errores en callbacks asíncronos

Un try/catch alrededor de una función que usa callbacks no captura errores que ocurran dentro del callback asíncrono, porque ese callback se ejecuta después, fuera del contexto del try. Este es un error clásico.

try-catch-fallido.js 
try {
  setTimeout(() => {
    throw new Error("Error dentro del callback");
  }, 1000);
} catch (error) {
  // Esto NUNCA se ejecuta
  console.error("Error capturado:", error);
}

// El error anterior rompe el programa porque el throw
// ocurre fuera del contexto del try/catch

La lección: los errores asíncronos solo se capturan con herramientas pensadas para asincronía — promesas, async/await o los eventos globales. Con esto cierras el nivel de asincronía y estás listo para explorar módulos en ES6+.
