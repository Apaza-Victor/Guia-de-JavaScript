Call Stack, Event Loop, Microtasks / Macrotasks

JavaScript tiene un solo hilo (single thread), pero gracias al Event Loop puede manejar miles de operaciones sin bloquearse. Entender cómo se orquestan el Call Stack, las Microtasks y las Macrotasks es la clave para predecir el orden exacto en que se ejecuta tu código asíncrono.

Call Stack: la pila de ejecución

El Call Stack es una estructura LIFO (Last In, First Out) donde se apilan las funciones a medida que se invocan. Cada vez que llamas a una función, su contexto se agrega al tope de la pila; cuando termina, se desapila. Si la pila se desborda (stack overflow), aparece el clásico error Maximum call stack size exceeded.

call-stack.js 
function a() { b(); }
function b() { c(); }
function c() { console.trace(); }

a();
// El trace muestra a → b → c apiladas en orden

Web APIs y el Task Queue

Cuando ejecutas setTimeout, fetch o un listener de evento, el motor delega la tarea a las Web APIs del navegador. Esas APIs colocan el callback en la Task Queue (o Macrotask Queue) cuando la condición se cumple. El Event Loop revisa constantemente si el Call Stack está vacío y, si lo está, toma la primera tarea de la cola y la empuja al stack.

macrotask-set-timeout.js 
console.log("1");

setTimeout(() => console.log("2"), 0);

console.log("3");
// Salida: 1, 3, 2

El setTimeout con 0 milisegundos no se ejecuta inmediatamente: su callback va a la Task Queue y espera a que el Call Stack esté vacío.

Microtask Queue: las promesas se saltan la fila

Las Microtasks (promesas, MutationObserver, queueMicrotask) tienen una cola separada con mayor prioridad. El Event Loop, antes de sacar una macrotask, vacía por completo la cola de microtasks. Por eso las promesas resueltas se ejecutan antes que cualquier setTimeout pendiente.

microtask-vs-macrotask.js 
console.log("1");

setTimeout(() => console.log("2"), 0);

Promise.resolve().then(() => console.log("3"));

console.log("4");
// Salida: 1, 4, 3, 2

El orden exacto: código síncrono (Call Stack) → Microtasks (Promesas) → Macrotasks (setTimeout, eventos). Por eso el "3" de la promesa sale antes que el "2" del setTimeout.

El ciclo completo del Event Loop

  1. Ejecuta todo el código síncrono del Call Stack.
  2. Saca y ejecuta una macrotask de la Task Queue (si el stack está vacío).
  3. Vacía toda la cola de Microtasks antes de pasar a la siguiente macrotask.
  4. Renderiza la interfaz si es necesario (requestAnimationFrame, paint).
  5. Vuelve al paso 2.
orden-completo.js 
console.log("A");

setTimeout(() => console.log("B"), 0);

Promise.resolve()
  .then(() => console.log("C"))
  .then(() => console.log("D"));

console.log("E");
// Salida: A, E, C, D, B

Resumen visual

El Event Loop prioriza siempre el código síncrono, luego las microtasks (promesas) y por último las macrotasks (timers, eventos). Dominar este flujo te permite razonar sobre cualquier orden de ejecución, incluso en los casos más anidados.
