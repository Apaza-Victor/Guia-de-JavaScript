Symbols

Symbol es el sexto tipo primitivo de JavaScript, introducido en ES6 para crear identificadores únicos e inmutables. Sirven como claves de propiedades que no colisionan con otras — ideales para metadatos, protocolos internos y evitar conflictos de nombres.

Crear Symbols

Cada llamada a Symbol() genera un valor único, aunque se le pase una descripción que solo sirve para depuración.

symbol-basico.js 
const sym1 = Symbol('id');
const sym2 = Symbol('id');

console.log(sym1 === sym2); // false — siempre son únicos
console.log(sym1.toString()); // "Symbol(id)"

Symbols como claves de objeto

Los Symbols pueden usarse como propiedades de objetos. A diferencia de las claves de tipo string, no aparecen en for...in ni en Object.keys(), lo que las hace útiles para propiedades "ocultas" o de metadatos.

symbols-como-clave.js 
const ID = Symbol('id');
const usuario = {
  nombre: 'Ana',
  [ID]: 12345
};

console.log(usuario.nombre);          // "Ana"
console.log(usuario[ID]);             // 12345
console.log(Object.keys(usuario));    // ["nombre"] — Symbol no aparece
console.log(Object.getOwnPropertySymbols(usuario)); // [ Symbol(id) ]

Symbol.for() y Symbol.keyFor()

Symbol.for(clave) crea o recupera un Symbol desde un registro global. Si ya existe un Symbol con esa clave, devuelve el mismo. Symbol.keyFor() obtiene la clave asociada a un Symbol global.

symbol-for.js 
const globalA = Symbol.for('app.version');
const globalB = Symbol.for('app.version');

console.log(globalA === globalB); // true — mismo Symbol global
console.log(Symbol.keyFor(globalA)); // "app.version"

const local = Symbol('app.version');
console.log(local === globalA); // false — local ≠ global

Well-known Symbols

JavaScript define Symbols incorporados que permiten personalizar el comportamiento de objetos. El más conocido es Symbol.iterator, que hace que un objeto sea iterable.

symbol-iterator.js 
const rango = {
  desde: 1,
  hasta: 3,
  [Symbol.iterator]() {
    let actual = this.desde;
    const fin = this.hasta;
    return {
      next() {
        return actual <= fin
          ? { value: actual++, done: false }
          : { done: true };
      }
    };
  }
};

console.log([...rango]); // [1, 2, 3]

Otros well-known symbols incluyen Symbol.toStringTag (personaliza Object.prototype.toString) y Symbol.toPrimitive (controla la conversión a primitivo).

otros-well-known.js 
class MiClase {
  get [Symbol.toStringTag]() {
    return 'MiClasePersonalizada';
  }
}
console.log(Object.prototype.toString.call(new MiClase()));
// "[object MiClasePersonalizada]"

// Symbol.toPrimitive — personaliza conversión a número/string
const producto = {
  precio: 100,
  [Symbol.toPrimitive](tipo) {
    if (tipo === 'number') return this.precio;
    return `$${this.precio}`;
  }
};
console.log(+producto);  // 100
console.log(`${producto}`); // "$100"

Symbol.iterator es el well-known symbol que más utilizarás. Cada vez que escribes for...of, [...arr] o Array.from(), JavaScript busca internamente este símbolo para saber cómo recorrer el objeto.

Evitar colisiones en librerías

Una aplicación práctica de Symbols es evitar colisiones de nombres al extender objetos de terceros. Al usar un Symbol como clave, te aseguras de no pisar propiedades existentes, incluso si otra librería usa la misma descripción.

sin-colision.js 
const metadata = Symbol('metadata');
const datos = { nombre: 'Ana' };

// Tu librería añade metadatos sin riesgo
datos[metadata] = { version: 1, fecha: Date.now() };

// Otra librería también usa Symbol('metadata') — pero es distinto
const otroMetadata = Symbol('metadata');
datos[otroMetadata] = { autor: 'otro' };

console.log(Object.getOwnPropertySymbols(datos).length); // 2
