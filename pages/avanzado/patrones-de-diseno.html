Patrones de diseño en JS

Los patrones de diseño son soluciones reutilizables a problemas comunes en el desarrollo de software. En JavaScript se implementan con soltura gracias a su flexibilidad — aunque el truco está en saber cuándo aplicarlos sin forzarlos.

Module Pattern

El patrón Module encapsula código en una unidad independiente con métodos y propiedades privadas. La forma clásica es una IIFE que devuelve un objeto con lo que quieres exponer.

module-pattern.js 
const Contador = (function () {
  let _cuenta = 0;

  function incrementar() {
    _cuenta++;
  }

  function obtener() {
    return _cuenta;
  }

  return { incrementar, obtener };
})();

Contador.incrementar();
Contador.incrementar();
console.log(Contador.obtener()); // 2
console.log(Contador._cuenta);   // undefined

Hoy en día los módulos nativos de ES6 (import / export) hacen lo mismo de forma más declarativa, pero el patrón sigue vivo en código legacy y bundles que no usan módulos.

Singleton

Garantiza que una clase tenga una única instancia y proporciona un punto de acceso global a ella. En JS puedes implementarlo con un objeto literal o con una clase que controle su construcción.

singleton.js 
class ConexionBD {
  constructor() {
    if (ConexionBD._instancia) {
      return ConexionBD._instancia;
    }
    this.conectado = false;
    ConexionBD._instancia = this;
  }

  conectar() {
    this.conectado = true;
    console.log('Conectado');
  }
}

const db1 = new ConexionBD();
const db2 = new ConexionBD();
console.log(db1 === db2); // true

Observer

Un objeto (sujeto) mantiene una lista de dependientes (observadores) y notifica cambios automáticamente. Es la base de la reactividad en librerías como Vue.

observer.js 
class Sujeto {
  constructor() {
    this.observadores = [];
  }

  suscribir(fn) {
    this.observadores.push(fn);
  }

  notificar(datos) {
    this.observadores.forEach(fn => fn(datos));
  }
}

const s = new Sujeto();
s.suscribir(d => console.log('A:', d));
s.suscribir(d => console.log('B:', d));
s.notificar('algo pasó');
// A: algo pasó
// B: algo pasó

Factory

Delega la creación de objetos a una función que decide qué tipo devolver según los parámetros. Útil cuando el proceso de construcción es complejo o condicional.

factory.js 
function crearVehiculo(tipo) {
  switch (tipo) {
    case 'coche':
      return { ruedas: 4, arrancar: () => 'brum brum' };
    case 'moto':
      return { ruedas: 2, arrancar: () => 'pum pum' };
    default:
      throw new Error('Tipo no soportado');
  }
}

const coche = crearVehiculo('coche');
console.log(coche.arrancar()); // brum brum
PatrónCuándo usarloRiesgo
ModuleAgrupar lógica relacionada con estado privadoAcoplarse a una implementación concreta
SingletonRecursos compartidos (configuración, pool de conexiones)Dificulta los tests y crea acoplamiento global
ObserverReaccionar a cambios sin acoplar emisor y receptorMuchos observadores pueden degradar rendimiento
FactoryCreación condicional o compleja de objetosPuede esconder demasiada lógica

No fuerces los patrones. JavaScript resuelve muchos problemas de forma más simple sin necesidad de un patrón específico. Si una solución directa funciona, no añadas la complejidad de un patrón por "buena práctica".
