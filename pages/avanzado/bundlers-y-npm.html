Bundlers modernos y npm

Ningún proyecto JS serio se escribe hoy sin un gestor de paquetes y un bundler. npm maneja las dependencias; Webpack, Vite y compañía empaquetan el código para producción.

npm: el gestor de paquetes

npm (Node Package Manager) es el gestor de paquetes por defecto de Node.js. Con npm init creas un package.json y con npm install <paquete> añades dependencias a tu proyecto.

comandos-basicos.sh 
npm init -y                    # crea package.json rápido
npm install lodash             # instala como dependencia
npm install -D vitest          # instala como devDependency
npm uninstall lodash           # elimina el paquete
npm run dev                    # ejecuta el script "dev"

El package.json es el corazón del proyecto: contiene metadatos, scripts, dependencias y configuración. El package-lock.json fija las versiones exactas para que todos los entornos instalen lo mismo.

package.json 
{
  "name": "mi-proyecto",
  "version": "1.0.0",
  "private": true,
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "test": "vitest"
  },
  "dependencies": {
    "lodash": "^4.17.21"
  },
  "devDependencies": {
    "vitest": "^2.0.0"
  }
}

Semver

npm usa versionado semántico (semver): MAJOR.MINOR.PATCH. El ^ permite actualizaciones de minor y patch, ~ solo patch, y sin prefijo fija la versión exacta.

semver.json 
{
  "^4.17.21": "compatible con 4.x.x",
  "~4.17.21": "solo parches 4.17.x",
  "4.17.21": "exactamente esa versión"
}

Bundlers: de módulos a bundles

Los bundlers toman tus archivos JS (y CSS, imágenes, etc.) y los empaquetan en uno o varios archivos optimizados para el navegador. Resuelven imports, eliminan código muerto (tree shaking) y aplican transformaciones.

webpack-vs-vite.js 
// Webpack: config explícita
// webpack.config.js
module.exports = {
  entry: './src/index.js',
  output: { filename: 'bundle.js' },
  module: { rules: [
    { test: /\.css$/, use: ['style-loader', 'css-loader'] }
  ]}
};

// Vite: zero-config, usa ESM nativo en dev
// vite.config.js (opcional)
import { defineConfig } from 'vite';
export default defineConfig({
  plugins: []
});

Módulos vs Bundles

En desarrollo, Vite sirve los módulos ES nativos sin empaquetar — el navegador los importa directamente. En producción, Vite usa Rollup para empaquetar y optimizar. Webpack, en cambio, empaqueta tanto en dev como en producción.

Para proyectos nuevos, empezá con Vite. Es más rápido, tiene configuración mínima y una experiencia de desarrollo excelente. Webpack sigue siendo una opción sólida para proyectos legacy o que necesitan configuraciones muy específicas.
