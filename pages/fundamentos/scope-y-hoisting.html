Scope y Hoisting

Dos conceptos fundamentales que determinan dónde existe una variable y cuándo puedes usarla. Sin entenderlos, bugs aparentemente mágicos te harán perder horas.

Scope global

Una variable declarada fuera de cualquier función o bloque vive en el scope global y es accesible desde cualquier parte del código. En el navegador, las variables globales se convierten en propiedades de window.

scope-global.js 
let global = "Estoy en el scope global";

function mostrar() {
  console.log(global); // ✅ accesible
}
mostrar(); // "Estoy en el scope global"

Evita contaminar el scope global: cada variable global es una variable que cualquier script puede sobreescribir. En proyectos grandes, usa módulos (import/export) para mantener todo encapsulado.

Scope de función

Con var, las variables declaradas dentro de una función solo existen dentro de ella. Fuera no son accesibles. Esto es válido también para let y const dentro de funciones.

scope-funcion.js 
function saludo() {
  var mensaje = "Hola";
  console.log(mensaje); // "Hola"
}

saludo();
console.log(mensaje); // ❌ ReferenceError: mensaje is not defined

Scope de bloque

let y const tienen scope de bloque: existen solo dentro de las llaves { } donde se declaran. Esta es la diferencia clave con var.

scope-bloque.js 
if (true) {
  let x = 10;
  const y = 20;
  var z = 30;
}
console.log(x); // ❌ ReferenceError
console.log(y); // ❌ ReferenceError
console.log(z); // 30 — var ignora el bloque

Hoisting

JavaScript "sube" las declaraciones al inicio de su scope antes de ejecutar el código. Pero la forma en que lo hace difiere según la palabra clave:

hoisting.js 
console.log(a); // undefined — var se "eleva" con undefined
var a = 5;

console.log(b); // ❌ ReferenceError: cannot access before initialization
let b = 10;

fn(); // ✅ funciona — function declaration se eleva completa
function fn() {
  return "ok";
}

Temporal Dead Zone (TDZ): con let y const, la variable existe (hoisting ocurre) pero no puedes acceder a ella hasta la línea de declaración. La zona entre el inicio del scope y la declaración es la "zona muerta temporal". Acceder a ella lanza ReferenceError.
