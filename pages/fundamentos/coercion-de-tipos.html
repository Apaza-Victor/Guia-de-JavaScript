Coerción de tipos: == vs ===

JavaScript intenta ayudarte convirtiendo tipos automáticamente, pero esa "ayuda" es la fuente de algunos de los bugs más difíciles de encontrar. Entender cuándo y cómo ocurre la coerción te da el control sobre tu código.

¿Qué es la coerción de tipos?

Es la conversión automática o manual de un valor de un tipo a otro. En JavaScript hay dos tipos de coerción: implícita (el motor la hace por ti) y explícita (tú forzas la conversión con funciones como String()).

Coerción implícita

Ocurre cuando usas operadores como == o + con valores de distinto tipo. JavaScript decide por ti cómo convertir antes de operar.

coercion-implicita.js 
console.log(5 == "5");     // true — "5" se convierte a 5
console.log(0 == false);    // true — false se convierte a 0
console.log("" == 0);       // true — "" se convierte a 0
console.log(null == undefined); // true — casos especiales

// Con el operador +, si hay un string, todo se vuelve string
console.log(1 + "2");       // "12" — número convertido a string
console.log("3" * "2");     // 6   — strings convertidos a número

El problema de == : las reglas de coerción implícita son difíciles de memorizar. Por ejemplo, [] == false da true y [] == ![] también da true. Por eso en código moderno se usa === siempre que sea posible.

Coerción explícita

Tú controlas la conversión usando las funciones constructoras String(), Number() y Boolean(). El código es más predecible y fácil de leer.

coercion-explicita.js 
let edad = "28";

// Explícita: de string a número
let numero = Number(edad);
console.log(numero + 2); // 30

// Explícita: de número a string
let texto = String(100);
console.log(texto.length); // 3

// Explícita: a booleano
console.log(Boolean(1));   // true
console.log(Boolean(0));   // false
console.log(Boolean(""));  // false
console.log(Boolean("Hi")); // true

Alternativas cortas: +"" convierte a número (unario +), "" + valor convierte a string, y !!valor convierte a booleano. Son coerción implícita disfrazada, pero se usan mucho en código real por su brevedad.

Comparación: == vs ===

La regla de oro: usa === por defecto. Solo recurre a == cuando sepas exactamente qué coerción ocurre y sea intencional —por ejemplo, comparar null == undefined para detectar valores nulos o indefinidos a la vez.
