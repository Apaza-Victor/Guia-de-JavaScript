Debugging con DevTools

El navegador es tu aliado más potente para entender qué está pasando (y por qué no está pasando lo que esperas). Chrome DevTools ofrece un depurador completo sin instalar nada.

Console: mucho más que console.log

El objeto console tiene varios métodos que dan más contexto que un log simple. Usa el adecuado según lo que necesites inspeccionar.

MétodoUso
console.log()Valor genérico
console.debug()Mensaje de depuración (oculto por defecto en consola)
console.warn()Advertencia (icono amarillo)
console.error()Error (icono rojo + stack trace)
console.table()Arrays/objetos en formato tabla
console.time() / timeEnd()Medir tiempo de ejecución
console.group() / groupEnd()Agrupar mensajes en la consola
console-metodos.js 
const usuarios = [
  { id: 1, nombre: 'Ana' },
  { id: 2, nombre: 'Luis' },
];

console.table(usuarios);

console.time('bucle');
for (let i = 0; i < 1000000; i++) {}
console.timeEnd('bucle');

console.group('Validación');
console.log('email: ok');
console.warn('teléfono no verificado');
console.groupEnd();

Breakpoints: pausa el código donde tú quieras

Los breakpoints son la herramienta estrella del debugging. Ponen pausa la ejecución en una línea concreta para que puedas inspeccionar variables, el call stack y el scope en ese momento exacto.

  • Line breakpoint: haz clic en el número de línea en la pestaña Sources.
  • Conditional breakpoint: haz clic derecho sobre el número de línea y escribe una condición (ej. valor > 10). Solo pausa cuando se cumple.
  • DOM breakpoint: desde el panel Elements, en un nodo del DOM, elige "Break on" → "attribute modification" o "subtree modification".
  • Event listener breakpoint: en Sources, despliega "Event Listener Breakpoints" y marca el evento que quieras interceptar (click, fetch, timeout, etc.).

Sources: el panel central

El panel Sources te muestra el archivo que se está ejecutando. Cuando el código se pausa en un breakpoint, puedes ver:

  • Call Stack: la pila de llamadas que llevaron hasta esta línea. Te dice qué función llamó a qué función.
  • Scope: las variables locales, de closure y globales accesibles en este punto.
  • Watch: expresiones personalizadas que evalúas en vivo (ej. usuario.nombre).

Desde aquí puedes avanzar línea por línea (F9), entrar a una función (F11), o saltar al siguiente breakpoint (F8).

debugger.js 
function calcularDescuento(precio, porcentaje) {
  // La palabra clave debugger actúa como breakpoint manual
  debugger;
  return precio - (precio * porcentaje / 100);
}

document.querySelector('button').addEventListener('click', () => {
  const total = calcularDescuento(500, 15);
  console.log(total);
});

Breakpoints vs console.log: console.log es rápido y útil, pero ensucia el código y requiere volver a ejecutar si olvidaste loguear algo. Los breakpoints no modifican el código, puedes añadirlos sobre la marcha, y te dan mucha más información (call stack, scope, variables en tiempo real). Para bugs complejos, los breakpoints ganan siempre.

Network y Performance

El panel Network es indispensable para depurar peticiones: muestra el método, la URL, el código de estado, los headers y el cuerpo de cada petición. Puedes filtrar por tipo (XHR, JS, CSS, img) y hasta simular una conexión lenta desde el throttling.

El panel Performance graba un perfil de actividad: cada función, cada layout, cada petición. Úsalo cuando el problema no es un error sino lentitud. La grabación te muestra qué operación consume más tiempo.

Con DevTools bajo el brazo, puedes enfrentarte a cualquier bug. La última pieza del rompecabezas de herramientas es Git, que protege tu código del caos de versiones y colaboración.
