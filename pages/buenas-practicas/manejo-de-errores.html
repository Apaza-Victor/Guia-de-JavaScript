Manejo de errores

El código falla. Lo que diferencia a un programa robusto de uno frágil no es que no tenga errores, sino cómo los maneja cuando aparecen.

try / catch / finally

La estructura base del manejo de errores en JavaScript. El bloque try ejecuta código que puede fallar; si ocurre una excepción, el control pasa al catch. El bloque finally se ejecuta siempre, haya o no error.

try-catch-finally.js 
try {
  const data = JSON.parse('{ json inválido');
  console.log(data);
} catch (error) {
  console.error('Error al parsear:', error.message);
} finally {
  console.log('Esto se ejecuta siempre');
}

El parámetro del catch es el objeto error. Aunque tradicionalmente se llamaba err o error, desde ES10 puedes omitir los paréntesis si no lo necesitas: catch { ... }. Úsalo con cuidado, porque silenciar errores sin mirarlos es una de las peores prácticas.

No tragues errores: un catch vacío (catch {}) oculta el problema y hace que el fallo se manifieste en otro lugar, mucho más difícil de rastrear. Como mínimo, haz un console.error o relanza el error.

throw y la clase Error

Puedes lanzar tus propios errores con throw. Casi siempre conviene lanzar una instancia de Error (o una subclase), porque incluye el stack trace que te dice exactamente dónde ocurrió el problema.

throw-error.js 
function dividir(a, b) {
  if (b === 0) {
    throw new Error('División por cero');
  }
  return a / b;
}

try {
  console.log(dividir(10, 0));
} catch (err) {
  console.error(err.message); // "División por cero"
  console.error(err.stack);   // traza completa
}

Errores personalizados

Para modelar distintos tipos de error, extiende la clase Error. Así puedes distinguirlos en el catch y responder de forma distinta según el tipo.

ApiError.js 
class ApiError extends Error {
  constructor(message, statusCode) {
    super(message);
    this.name = 'ApiError';
    this.statusCode = statusCode;
  }
}

async function obtenerUsuario(id) {
  const res = await fetch(`/api/usuarios/${id}`);
  if (!res.ok) {
    throw new ApiError('Usuario no encontrado', res.status);
  }
  return res.json();
}

try {
  const usuario = await obtenerUsuario(999);
} catch (err) {
  if (err instanceof ApiError) {
    console.error(`API error ${err.statusCode}: ${err.message}`);
  } else {
    console.error('Error inesperado:', err);
  }
}

Error.cause

Desde ES2022 puedes encadenar errores con la propiedad cause. Es útil cuando atrapas un error de bajo nivel y quieres lanzar uno de más alto nivel sin perder la información original.

error-cause.js 
try {
  await fetch(url);
} catch (err) {
  throw new Error('No se pudo conectar con el servidor', { cause: err });
}

Patrones de manejo

Más allá de la sintaxis, el manejo de errores tiene patrones que marcan la diferencia en producción:

  • No tragar errores: siempre loguea o relanza.
  • Fallback: si una API externa falla, intenta con un caché o un valor por defecto.
  • Barrera de errores: en el punto de entrada (event listener, handler HTTP), atrapa todo para que no se propague sin control.
  • Errores como datos: en lugar de lanzar, devuelve un objeto { error, data } — común en Go, cada vez más visto en JS funcional.

Dominar el manejo de errores te prepara para escribir código que no solo funciona cuando todo va bien, sino que se recupera con elegancia cuando algo sale mal. El siguiente tema lo complementa con tests que verifican que esos escenarios funcionan.
